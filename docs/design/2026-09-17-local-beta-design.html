  • CLI 覆盖率仅 67%，真实模型/真实仓库证据不足

3. 目标本地架构

只有一套内核、一份权威知识。Web、CLI 和 MCP 都是本机入口；不建设云端、不双向同步，也不把向量库当作事实源。

数据原则：Claim、Evidence、知识对象及人工 Overlay 是权威资产；全文索引、未来可能的向量索引、页面和缓存都是可重建投影。下一轮默认不引入向量数据库，除非 M8 证明它对任务质量有显著收益。

4. 产品旅程与界面

首页不再从“文件列表”开始，而从用户任务开始。底层 ID、哈希和诊断信息保留在审计抽屉里，不占据普通阅读路径。

① 安装与预检检查 Python、Git、解析器、模型配置和磁盘空间。
② 添加仓库选择本地目录，配置 include/exclude 和知识目标。
③ 构建知识后台任务显示阶段、进度、费用、失败和可恢复动作。
④ 阅读与审计架构、模块、流程、规则、技术栈、Claim 与源码证据。
⑤ Ask先返回证据型结果；可选模型摘要必须逐条引用。
⑥ 交给 Agent预览上下文，再通过 MCP/CLI 提供同一份知识。

5. 下一轮里程碑

不承诺日期，只承诺退出条件。每个里程碑都必须同时包含底层能力、用户可见流程、真实仓库证据和自动回归。

M9

本地产品基座

把“源码包”变成可安装、可启动、可诊断的本地应用。

  • 一条命令启动本地 API、Worker 与 Web
  • 统一配置、数据目录、迁移与备份边界
  • 预检、首次启动向导、错误码与诊断包
  • 拆分 Wiki/CLI 等超大模块的明确接口
退出：全新机器按文档完成安装并打开空仓首页。
M10

可靠仓库接入与解析

任何解析器崩溃都不能带走主进程，能力不足必须显式降级。

  • 解析 Provider 能力合同与子进程隔离
  • 崩溃、超时、取消、重试和恢复
  • 增量索引、排除规则和仓库快照状态
  • Python / TS / C 等真实仓 smoke corpus
退出：三个外部仓库重复构建，崩溃可诊断且应用仍可用。
M11

建库任务闭环

用户能计划范围、观察进度、处理失败并得到可审计产物。

  • 知识计划、范围选择和预计成本
  • 后台队列、阶段进度、暂停/继续/取消
  • Claim 验证、人工 Overlay 与冲突处理
  • 历史、差异、重新构建和安全回滚
退出：失败任务无需清目录即可恢复并发布一致 generation。
M12

知识阅读 Beta

重做信息架构与详情页，把可信状态转化为可理解的界面。

  • 概览、页面树、模块/流程/规则/技术栈
  • Claim 卡片、行级引用、源码跳转
  • 覆盖率、缺口、过期、冲突与降级状态
  • 响应式、键盘操作、可访问性和空状态
退出：用户可从概览在三次操作内定位结论及其源码证据。
M13

Ask 与 Agent 端面

人和 Agent 使用同一检索、门禁与来源，不产生第二套答案逻辑。

  • Claim 级 FTS、过滤、排序和相关对象
  • 证据型 Ask；可选模型摘要逐句引用
  • MCP/CLI/API 能力与错误语义一致
  • Task Context 预览、预算和使用记录
退出：同一问题在 Web、CLI、MCP 返回一致证据集合。
M14

真实价值证明与发布

完成 M8 实验，把“感觉有用”变成可重复的数据。

  • 真实模型、真实仓库和冻结任务集 A/B
  • 正确率、证据充分率、延迟、成本、陈旧率
  • 冷启动、增量更新、大仓与故障注入测试
  • 安装包、升级/卸载、文档和 Beta 发布门禁
退出：独立重跑可复现实验，并达到预先冻结的质量阈值。

6. 范围边界

本轮包含

  • 个人开发者单机完整体验
  • 真实仓库解析可靠性
  • 本地 Web、CLI、MCP 三端一致
  • 可信知识、人工覆盖与历史
  • 可选模型能力与明确成本
  • 可复制的 M8 产品价值实验

本轮明确不做

  • 云服务、多租户、组织权限与计费
  • 本地—云端实时同步
  • 手机原生端、桌面原生壳
  • 多仓知识图谱和组织级搜索
  • 默认向量数据库
  • 没有真实收益证据的生成式功能
