# CodeWiki 项目原则

本文件是 CodeWiki 项目特定铁律的单一事实源。`CLAUDE.md` 与 `AGENTS.md`
只建立索引，不复制本文件全文。

## P-001 · 重大设计同步四个权威表面

重大产品、架构或路线设计获得确认后，必须在同一变更中同步：设计原件、根
`README.md`、`docs/README.md` 和 `docs/knowledge/product/decision-log.md`。
四处不一致时，设计尚未完成。

## P-002 · 每次冻结都执行完整封存审计

每次里程碑冻结、中期冻结和最终项目封存，必须执行同一套闭环，不得只打标签、
写总结或复制聊天记录：

1. **同步与定界**：拉取 `origin/main`，记录审计 commit、环境和当前批准范围；
   先区分“已交付”“已计划未实现”“明确不做”，不得把计划当成功能。
2. **内部总审计**：检查功能、代码、依赖、安全、测试、CLI/MCP/Web 端面、可访问性、
   安装与运行路径；用户界面结论必须使用本轮重新采集的截图或明确记录无法取证。
3. **行业横评**：只使用当次重新核验的官方资料，与同类和可借鉴产品逐项对照；
   每条差距都映射到现有目标，不能借竞品之名扩大项目范围。
4. **范围过滤**：遗漏当前承诺、可信性缺口和封存风险进入关闭清单；新业务、云化、
   多租户、组织功能等越界想法只记为“不在范围”，不自动进入 Roadmap。
5. **仓库清理**：盘点重复、过期、孤儿、错误命名、生成物和悬空引用；重命名先写
   路径迁移映射并用 `git mv`；删除、迁移等红线动作先列出精确目标并取得用户批准。
6. **知识沉淀**：保证素材层、静态知识层、规格/计划层三者齐全；补齐来源目录、
   演进时间线、决策日志、as-built 架构、行为参考、限制与未决项。
7. **归档包**：保存审计报告、验证证据、截图、竞品来源、计划状态、演进记录、
   文件清单和未完成项处置；动态外部资料必须同时保留核验日期与静态摘要。
8. **关闭门禁**：测试/链接/安全检查通过，README、HANDOFF、文档索引与代码一致，
   工作树干净且 `HEAD == origin/main` 后，才可声明某里程碑或项目可封存。

### 关闭判断

- **可关闭**：批准范围全部完成，或未完成项已由用户明确取消/延期并记录；所有门禁通过。
- **可冻结但不可宣称完成**：当前版本可复现，但仍有 active 计划或外部验证缺口。
- **不可冻结**：存在数据安全、错误完成声明、无法复现、文档与实现冲突或未处置的 P0/P1。

### 必备归档物

- 一份权威审计报告和一份可勾选的关闭计划；
- 一份从起源到当前 commit 的演进时间线；
- 一份静态知识库总索引和素材来源清单；
- 一份“承诺—实现—测试—证据”追踪表；
- 一份竞品矩阵，逐条标明“补齐 / 保持现状 / 不在范围”；
- 一份已知限制、外部依赖和恢复方式清单；
- 本轮验证命令、结果、环境、截图和最终 commit。
